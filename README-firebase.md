# Firebase в FUNDING / WATCH

Конфиг вашего проекта (`funding-watch-3c7cb`) уже встроен прямо в `funding-watch.html` — ничего копировать и вставлять на странице не нужно. Осталось включить нужные настройки в самой консоли Firebase (один раз) — это займёт пару минут.

`apiKey` в конфиге — не секретный ключ, его можно спокойно хранить в открытом клиентском коде. Реальная защита данных обеспечивается правилами Firestore и списком включённых провайдеров входа (шаги 1 и 3 ниже), а не сокрытием конфига.

---

## 1. Включить вход по email и паролю (Authentication)

1. Откройте проект [funding-watch-3c7cb](https://console.firebase.google.com/project/funding-watch-3c7cb) в консоли Firebase.
2. В левом меню: **Build → Authentication**.
3. Вкладка **Sign-in method** → **Add new provider** → выберите **Email/Password**.
4. Включите первый тумблер **Email/Password** → **Save**. Второй тумблер («Email link — passwordless sign-in») включать не нужно, сайт его не использует.

По умолчанию Firebase не требует подтверждения email при регистрации — можно входить сразу после регистрации.

---

## 2. Создать базу Firestore

1. В левом меню: **Build → Firestore Database** → **Create database**.
2. Выберите регион (любой ближайший к вам, менять потом нельзя).
3. Режим запуска — можно **Start in test mode**, но перед тем как оставить это надолго, обязательно настройте правила из шага 3 ниже.

---

## 3. Настроить правила безопасности Firestore

По умолчанию (или в тестовом режиме) база либо закрыта, либо временно открыта всем — оба варианта не годятся для постоянной работы. Нужно ограничить доступ так, чтобы каждый пользователь видел только свои настройки.

1. **Firestore Database → Rules**.
2. Замените содержимое на:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

3. **Publish**.

Это разрешает пользователю читать и писать только документы внутри `users/<его_uid>/...` — ровно то, что использует сайт (`users/{uid}/settings/main`).

---

## 4. Пользоваться сайтом

1. Откройте `funding-watch.html` в браузере — Firebase подключится автоматически.
2. Нажмите **«Войти по почте»** в верхней панели — откроется окошко входа.
3. При первом визите переключитесь на вкладку **«Регистрация»**, укажите email и пароль (минимум 6 символов) → **«Зарегистрироваться»**. При следующих визитах — вкладка **«Вход»** с теми же данными.
4. Если забыли пароль — введите email в форме и нажмите **«Забыли пароль?»**, придёт письмо со ссылкой для сброса.

После входа значок рядом с кнопкой «Выйти» покажет **☁ синхронизировано** — с этого момента список монет и порог алерта, которые вы задаёте в панели «Применить», автоматически сохраняются в Firestore и подтянутся на любом другом устройстве/браузере после входа теми же email и паролем.

---

## Проверка, что всё работает

- Измените список монет → нажмите **Применить** → откройте тот же `funding-watch.html` в другом браузере (или режиме инкогнито), войдите тем же email и паролем — список монет должен подтянуться автоматически.
- Откройте DevTools (F12) → вкладка **Console** — если что-то не сохраняется, там будут предупреждения `cloud save failed` / `cloud load failed` с текстом ошибки Firebase (чаще всего — не опубликованы правила из шага 3, либо не включён провайдер Email/Password из шага 1).

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| В окошке входа ошибка «Ошибка: auth/configuration-not-found» или «operation-not-allowed» при регистрации | Провайдер Email/Password не включён | Шаг 1 |
| «Этот email уже зарегистрирован» на вкладке «Регистрация» | Аккаунт с таким email уже существует | Переключитесь на вкладку «Вход» и используйте пароль от него, либо «Забыли пароль?» для сброса |
| «Аккаунт с таким email не найден» на вкладке «Вход» | Ещё не регистрировались с этим email | Переключитесь на вкладку «Регистрация» |
| «Неверный email или пароль» | Опечатка в пароле или email относится к другому провайдеру | Проверьте раскладку/Caps Lock, либо сбросьте пароль через «Забыли пароль?» |
| Письмо для сброса пароля не приходит | Ушло в спам, либо не настроен шаблон писем | Проверьте папку «Спам»; шаблон можно посмотреть в Authentication → Templates → Password reset |
| Настройки не сохраняются, в консоли `permission-denied` | Правила Firestore не опубликованы или неверны | Шаг 3 |
| Панель «Firebase» на сайте пишет «Ошибка инициализации Firebase» | Конфиг в файле повреждён (например, HTML редактировали вручную) | Сверьте блок `firebaseConfig` в `funding-watch.html` с оригиналом из Project settings → General → Your apps |

## Если нужно подключить другой Firebase-проект

Конфиг зашит прямо в код — заменить его можно только правкой файла. В `funding-watch.html` найдите блок:

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

и замените значения на конфиг своего проекта (Project settings → General → Your apps → SDK setup and configuration → Config в консоли Firebase). После этого повторите шаги 1–3 этого README уже для нового проекта.
